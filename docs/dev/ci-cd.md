# CI/CD and releases

The pipeline is made of GitHub Actions workflows in
[`.github/workflows`](../../.github/workflows), chained with `workflow_run`.

| Workflow | File | When | What it does |
|---|---|---|---|
| Tests | `1-tests.yml` | push and pull requests on `main`/`master`, manual | Frontend: type-check, tests, build. Backend: `cargo fmt --check`, `clippy -D warnings`, `cargo test`, PostgreSQL-backed suites. Each side runs only if its directory changed. See [Testing](testing.md). |
| Build images | `2-build-images.yml` | after Tests succeeds on `main`/`master`/`releases/**`, manual | Builds `klask-backend` and `klask-frontend` (only the side that changed), pushes them to `ghcr.io/klask-dev/`, and scans them with Trivy. |
| Publish Helm chart | `3-publish-helm.yml` | after the `Release` workflow, on a published release, manual | Packages `charts/klask` and pushes it to `oci://ghcr.io/klask-dev/klask`. |
| Release | `4-release.yml` | after Tests succeeds on `main`/`master`, manual | Runs semantic-release (below). |

## Image tags

Tags are generated by `docker/metadata-action` in `2-build-images.yml`:

- `<branch>` (for example `master`) and `pr-<number>`;
- `sha-<commit>`;
- `<version>`, `<major>.<minor>` and `<major>` when built from a version tag;
- `latest` on the default branch.

`docker-compose.yml` uses `latest` unless `KLASK_IMAGE_TAG` is set.

## Chart versions

`3-publish-helm.yml` sets the chart `version` and `appVersion` before packaging:
the release tag (without a leading `v`) for a release; the version found in
`Chart.yaml` for a build of `main`/`master`; that version with a `-pr<number>`
or `-dev` suffix otherwise. Installation is described in
[Helm](../admin/helm.md).

## Releases

Releases are automated by [semantic-release](https://semantic-release.gitbook.io)
(configuration in `.releaserc.json`). On every push to `master` that passes the
tests, commit messages since the last release decide the next version:

| Commit type | Release |
|---|---|
| `feat` | minor |
| `fix`, `perf` | patch |
| any type with a breaking change (`!` or a `BREAKING CHANGE:` footer) | major |
| `docs`, `refactor`, `chore`, `test`… | none by themselves |

When a release is due, semantic-release generates the entry in `CHANGELOG.md`
(do not edit it by hand), runs `scripts/update-versions.sh <version>` to set the
version in `klask-rs/Cargo.toml`, `klask-react/package.json` and
`charts/klask/Chart.yaml`, commits these files, tags the release and creates the
GitHub release. Write commit messages accordingly: see
[CONTRIBUTING.md](../../CONTRIBUTING.md#commit-messages).
