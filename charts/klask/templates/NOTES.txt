⚠️ SECURITY NOTES
==================

1. Auto-generated Secrets (INFRA-012)
-----------------------------------
If ENCRYPTION_KEY and JWT_SECRET were auto-generated by Helm (check the output above),
please replace them with cryptographically secure values BEFORE PRODUCTION USE.

The auto-generated values use Helm's randAlphaNum which is NOT cryptographically secure.
Replace with values generated using a cryptographically secure RNG:

  # Generate secure random values (64 hex chars = 32 bytes)
  ENCRYPTION_KEY=$(openssl rand -hex 32)
  JWT_SECRET=$(openssl rand -hex 32)

  # Update the secrets immediately
  helm upgrade {{ include "klask.fullname" . }} \
    --namespace {{ .Release.Namespace }} \
    --set backend.auth.encryptionKey=$ENCRYPTION_KEY \
    --set backend.auth.jwtSecret=$JWT_SECRET

To verify which secrets are in use:
  kubectl get secret {{ include "klask.fullname" . }}-backend-auth -n {{ .Release.Namespace }} -o yaml

2. Database TLS/SSL (INFRA-011)
--------------------------------
{{ if .Values.postgresql.enabled }}
For embedded PostgreSQL: TLS between backend and database is not enabled by default
(in-cluster communication). To enable TLS, configure PostgreSQL and update the backend
connection string to include ?sslmode=require.

For external PostgreSQL: Ensure your DATABASE_URL includes TLS parameters:
  - Add to your URL: ?sslmode=require (or verify-ca / verify-full for stricter verification)
  - Example: postgresql://user:password@host:5432/klask?sslmode=require
{{ else }}
For external PostgreSQL: Verify your DATABASE_URL includes TLS parameters:
  - Current URL should include: ?sslmode=require (or verify-ca / verify-full for stricter verification)
  - Example: postgresql://user:password@host:5432/klask?sslmode=require
{{ end }}

Pod Security Standards:
=======================
Ensure your namespace has Pod Security Standards enforced:

  kubectl label namespace {{ .Release.Namespace }} \
    pod-security.kubernetes.io/enforce=restricted \
    pod-security.kubernetes.io/enforce-version=latest \
    --overwrite

1. Get the application URL by running these commands:
{{- if .Values.ingress.enabled }}
{{- range $host := .Values.ingress.hosts }}
  {{- range .paths }}
  http{{ if $.Values.ingress.tls }}s{{ end }}://{{ $host.host }}{{ .path }}
  {{- end }}
{{- end }}
{{- else if contains "NodePort" .Values.frontend.service.type }}
  export NODE_PORT=$(kubectl get --namespace {{ .Release.Namespace }} -o jsonpath="{.spec.ports[0].nodePort}" services {{ include "klask.fullname" . }}-frontend)
  export NODE_IP=$(kubectl get nodes --namespace {{ .Release.Namespace }} -o jsonpath="{.items[0].status.addresses[0].address}")
  echo http://$NODE_IP:$NODE_PORT
{{- else if contains "LoadBalancer" .Values.frontend.service.type }}
     NOTE: It may take a few minutes for the LoadBalancer IP to be available.
           You can watch the status of by running 'kubectl get --namespace {{ .Release.Namespace }} svc -w {{ include "klask.fullname" . }}-frontend'
  export SERVICE_IP=$(kubectl get svc --namespace {{ .Release.Namespace }} {{ include "klask.fullname" . }}-frontend --template "{{"{{ range (index .status.loadBalancer.ingress 0) }}{{.}}{{ end }}"}}")
  echo http://$SERVICE_IP:{{ .Values.frontend.service.port }}
{{- else if contains "ClusterIP" .Values.frontend.service.type }}
  export POD_NAME=$(kubectl get pods --namespace {{ .Release.Namespace }} -l "app.kubernetes.io/name={{ include "klask.name" . }},app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=frontend" -o jsonpath="{.items[0].metadata.name}")
  export CONTAINER_PORT=$(kubectl get pod --namespace {{ .Release.Namespace }} $POD_NAME -o jsonpath="{.spec.containers[0].ports[0].containerPort}")
  echo "Visit http://127.0.0.1:8080 to use your application"
  kubectl --namespace {{ .Release.Namespace }} port-forward $POD_NAME 8080:$CONTAINER_PORT
{{- end }}

2. Check the status of your deployment:
   kubectl get pods -l "app.kubernetes.io/instance={{ .Release.Name }}"

3. View backend logs:
   kubectl logs -l "app.kubernetes.io/name={{ include "klask.name" . }},app.kubernetes.io/component=backend"

4. View frontend logs:
   kubectl logs -l "app.kubernetes.io/name={{ include "klask.name" . }},app.kubernetes.io/component=frontend"
